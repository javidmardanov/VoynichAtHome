# Current design: research and public release

This document supersedes the two branch blueprints, SYNTHESIS, PLAN and BUILD_PLAN. The owner approved this direction on 2026-09-05. Historical designs remain in `docs/history` and Git history.

## Purpose and claims

Search for testable explanations, measure reliability, and publish evidence. Recovering a known message, finding a manuscript candidate, and supporting a scientific conclusion are separate outcomes. No percentage decoded, speculative success probability, or claim that credit measures correctness.

First measure known-message recovery on Latin and Italian. Use ordinary substitution, homophonic substitution, and documented verbose encodings beginning with Naibbe. Label published constructions and randomized extensions separately; preserve rules that prevent ambiguous output. Compare beam search with independent-start key improvement using fixed character n-gram models trained on different source works. Never rewrite decoder output into fluent prose.

Test 1,000, 5,000 and 20,000 normalized characters at 1, 8 and 64 starts. Split training, development and evaluation by source work. Keep answers and keys outside solver inputs. Publish character recovery, ambiguous readings, failures, time, memory and all negative controls at equal budgets. Use a small development panel, freeze settings, then 100 new cases per reported condition. Concealed solver inputs are not independently administered trials. Measure the benefit of added starts before scaling volunteer work.

Only benchmark-supported encoding families can enter a bounded manuscript campaign. Register exact transcriptions, passages, glyph grouping, spaces, language resources, algorithm, seeds, budget, scores, controls and stopping. Study major text groups separately. Preserve boundaries, uncertainty and exclusions. Publish mapping rules, unchanged output and exceptions. Candidate promotion needs substantial text, registered comparisons, independent reproduction and specialist scrutiny. Existing manuscript results remain exploratory.

## Software and users

Rust kernel, native CLI and WASM share scientific contracts. SvelteKit and TypeScript provide the site and interfaces. Initial hosting is Cloudflare Workers, D1 and R2. Better Auth enables optional Google and GitHub accounts. GitHub Actions builds, tests and publishes releases. Desktop installers and GPUs are deferred.

Versioned contracts distinguish scientific work from leases and submission attempts. Work identifies experiment, inputs, algorithm, numeric profile, initial state and fixed budget. Supported work types are generation, decoding search and verification. Persist configuration, seed, budget, output and validation for each run. Deterministic replay can recover intermediate search state. Legacy kernel 0.2 fixtures remain reproducible; search steps are not counted as separate hypotheses.

Anyone can start as a guest. Accounts provide multiple-device contributions, teams and optional public profiles/rankings. Public visibility requires opt-in. Claiming guest contributions requires control of the guest session and is idempotent. Credit follows checks and a published fixed work estimate. Delete identity while retaining anonymous research; support session revocation and moderation.

Computation starts only on click: one worker, conservative intensity, hidden-tab pause by default. Stop terminates the worker immediately. Bound work, checkpoint, persist results for retry and handle offline/reload. Do not depend on battery detection. Duplicate execution, candidate checks and trusted replay provide distinct validation evidence. Anonymous IDs do not prove independence or honest execution. Promote report candidates only after rescoring. Approved module digests/imports, signed releases and provenance reduce supply risks; a compromised website remains a documented risk.

The site serves volunteers, researchers and contributors: introduction, contribution controls, campaigns/results, browser verification, optional profiles/teams, methods, downloads, status and structured GitHub experiment proposals. English first with translation structure; keep useful translated material.

## Operations and release gates

1. Consolidate, correct science, document rights, pass existing checks.
2. Implement recovery searches and publish measured performance and limitations.
3. Complete guest, account, work, verification, reports, teams and owner controls end to end.
4. Rehearse in deployed staging: load, overload, shutdown, recovery, rollback, backup restoration and browser resource control.
5. Owner-authorized tagged public release with reproducible manifests, operating guide and accurate status.

Test native/browser parity; retry without credit duplication; expired/late/duplicate/conflicting/malformed/revoked submissions; start/pause/stop/hidden/reload/offline; account migration/logout/deletion/team changes; keyboard/mobile/unsupported-device flows; 25 simultaneous clients then orderly overload; backup restore and rollback; reproduction from manifest. Operational failures are not scientific failures.

When a campaign ends, serve no new work. A new campaign or declared continuation is required. A justified recovery study can open even when harder encodings remain unsolved; do not present unrestricted manuscript search as ready.

## Ownership and cost

The human owner is release authority. No invented reviewers or endorsements. Target $10/month with approval before paid setup. Use a free provider address initially. Hosted checks must not depend on the owner's computer. Track traffic, storage and trusted CPU; reserve resources to finish issued work, pause assignments before the budget is exhausted. Alerts are not a provider-enforced spending cap.

Original code is open source; each transcription, text, image, font and imported implementation retains its own rights record. Completion means a reliable, documented, reproducible public platform and justified research program. Decipherment is not a release promise.
